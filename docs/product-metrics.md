# Проверка бизнес-эффекта

Гипотеза: материал, соответствующий текущей задаче и следующему действию, помогает начать полезное обучение. После получения пользы часть пользователей выбирает релевантный платный продукт и возвращается чаще. **Конверсия и эффект ещё не измерены.**

## События

| Событие | Точное определение | Состояние |
|---|---|---|
| recommendation_generated | API вернул маршрут | можно фиксировать в прототипе, без содержимого запроса в логах |
| recommendation_viewed | карточка была видима пользователю, а не просто сгенерирована | нужна клиентская аналитика видимости |
| material_opened | пользователь открыл карточку/источник | переход UI есть, аналитическое хранилище события не подключено |
| helpful / not_relevant / known / completed | явная отметка пользователем | хранится в БД приложения |
| learning_started | платформа зафиксировала начало изучения | нужна интеграция с Альфа-Курсом |
| next_step_started | начало следующего материала того же маршрута | нужна связка route_id и событий платформы |
| purchase_completed | подтверждённая платформой оплата, без отмены в заданном окне | в MVP отсутствует, клик не считается покупкой |
| active_day | уникальный календарный день с содержательной активностью по единой timezone | требуется аналитика платформы |

## A/B-эксперимент

Единица рандомизации — стабильный обезличенный пользователь, закреплённый за вариантом на весь эксперимент. A — подбор по теме, B — персональный маршрут. Одинаковые каталог, цены и доступ; стратификация по новому/возвращающемуся пользователю и платформе. Историческую покупку нельзя ошибочно посчитать как эффект рекомендации.

Основная метрика: доля включённых пользователей с подтверждённой покупкой образовательного продукта в заранее зафиксированном окне, например 14 дней. Это предлагаемое окно, его нужно согласовать с фактическим циклом покупки. Вторичная: число активных дней за такое же окно. Дополнительно CTR видимых рекомендаций, начало/завершение обучения и переход к следующему шагу.

Ограничители: ошибки API, p95 задержки, отказ от сценария, доля негативных отметок и ручная оценка нерелевантной выдачи. Увеличение покупок не считается успехом, если нарушена доступность или заметно выросла нерелевантность.

До запуска: определить базовую конверсию, минимальный полезный эффект MDE, alpha, мощность, число вариантов, размер выборки и правила множественных сравнений. Без этих данных нельзя честно назвать достаточное N или гарантированную длительность. Ориентир по календарю — минимум два полных недельных цикла плюс созревание окна покупки; окончательный срок зависит от трафика и расчёта мощности.

Анализ: intention-to-treat, проверка sample ratio mismatch, доверительные интервалы и заранее заданные критерии успеха. Не останавливать тест при первом удачном p-value. При наличии покупок до эксперимента рассмотреть стратификацию/CUPED, если метод корректен для метрики. Учитывать сезонность, рекламные кампании, другие рекомендации и повторные устройства. До подтверждения результата внедрение ограничивается внутренним пилотом.
