# Документация — дополнение к корневому AGENTS.md

Прочитать `../AGENTS.md`. Текущее состояние — STATUS; очередь задач — NEXT/plan; выполненные действия — worklog. Исторические аудиты и release-файлы описывают свою версию, а не текущую готовность.

- Писать конкретно: поведение, причина, фактическая проверка и ограничения. Не превращать план или наличие файла в выполненную работу.
- ТЗ и официальные уточнения отделять от пожеланий участников, предположений и реплик в приложениях. Исходную переписку, контакты, ссылки встреч и закрытые вложения не копировать.
- Примеры и изображения для публикации только DEMO/авторские. Не добавлять реальные подробные выдачи, source ID, историю, персональные данные или платный контент.
- Не заявлять независимую точность, human labels, рост конверсии или превосходство над baseline на основе score/оценки агента. Наборы, использованные при настройке, явно называть регрессией.
- Новичку достаточно стандартного DEMO. Не писать как обязательное наличие частной модели/дампа/чужого абсолютного пути или установленного у владельца инструмента.
- Проверять относительные ссылки и команды. В README давать ссылку на канонический документ вместо копирования длинных инструкций, которые быстро расходятся.
- Инструкции для AI хранить в AGENTS.md и коротких маршрутизаторах; не дублировать правила в нескольких независимых копиях. Личные настройки IDE, навыки из домашней папки, токены и локальные автоматизации не переносить в Git.
- Опубликованные release-документы и теги сохранять как историю. Текущие PDF/PPTX должны соответствовать выбранной версии; не подменять их репетиционным комплектом.

Для изменения только текста: проверить ссылки, `git diff --check`, `python scripts/check_public_files.py`. Не заявлять повторное прохождение приложения и не менять VERSION ради документации.
