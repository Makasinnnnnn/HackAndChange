# Подбор материалов — pipeline v6

Версии: e5-hybrid-personal-v6 / lexical-personal-v6, baseline topic-baseline-v4. Релиз 1.2.0. Генеративная LLM уточняет задачу отдельно, не создаёт каталог и не ранжирует материалы.

## Компоненты

| Модуль | Ответственность |
|---|---|
| engine.py | Оркестрация, Route и раскрытие непокрытых частей |
| recommendation/intent.py | Исходный запрос, положительная задача, ограничения, форма бизнеса, площадки, нормализация |
| recommendation/tasks.py | Контролируемые операции и доказательства по title/description, неизменяемый ограниченный кеш |
| recommendation/eligibility.py | Жёсткие конфликты до confidence: доступ, отрасль, операция, объект, направление, формат, ограничения |
| recommendation/index.py | Один индекс каталога: word/char TF-IDF и опциональная локальная E5 |
| recommendation/ranking.py | Ограниченный профильный бонус, покрытие разных операций, разнообразие |
| recommendation/explanation.py | Проверяемые причины, диагностические сигналы и предлагаемый следующий шаг |
| recommendation/policy.py | Веса, пороги, версии |

## Алгоритм

1. Сохранить оригинальный запрос для UI. В поисковой копии убрать отвергнутую альтернативу и предварительное условие вроде проверки идеи до аренды. Нормализация нескольких распространённых опечаток — контролируемая, не универсальная коррекция.
2. Выделить конкретные операции и ограничения. Слово «спрос» не равно «спросить», найм не равен удержанию, регистрация ИП не равна регистрации профиля на площадке.
3. Исключить неподходящее до оценки доверия. Для personal дополнительно исключить completed/known/not_relevant. История исходного пользователя не связывается с посетителем автоматически.
4. Получить evidence. E5 делает один encode запроса; cosine — сходство, не вероятность. Если нет известных операций/тем/отрасли, нужны информативные совпадения заголовка; вопросительные слова сами не допускают материал. Если операция подтверждена, она не должна отсеиваться как неизвестный запрос из-за низкого cosine.
5. Оценить совпадения задачи по title/description, а не только общей метке. Положительный профильный бонус ограничен и не воскрешает исключённого кандидата. Неизвестные поля не дают преимущество через знаменатель.
6. Порог близости применяется внутри каждой операции, чтобы первая часть составного запроса не подавляла вторую. Personal сначала покрывает ещё не представленные операции, затем добавляет разнообразие. coverage_priority / coverage_bonus / diversity_penalty раскрываются раздельно.
7. Персональная подборка — до трёх сильных карточек. Если отрасль не подтверждена показанными карточками, scope=general. Нераспознанная/непокрытая задача не заменяется случайным хвостом; непокрытая распознанная часть обозначается в notice.

Фиксированный рекламный бюджет допускает повторные продажи, маржу, конверсию, снижение затрат, эффективность рекламы или органическое продвижение при свидетельстве в метаданных. Запрета любой рекламы нет. Отказ от франшизы, отсутствие сотрудников, запрет найма, сохранение сотрудников, нужный формат и явно названная площадка проверяются до ранжирования. Общие слова о теме недостаточны.

## Baseline и объяснения

Baseline использует тот же каталог и общие ограничения запроса/доступа. Он считает lexical/topic score и подтверждение операции без E5, личного профиля, истории и персонального покрытия/разнообразия. Это отдельный расчёт, не копия personal со снятыми подписями. Общие правила допуска — часть одинаковых условий сравнения. Численные score двух алгоритмов напрямую не сравнивать; более высокий score не доказывает улучшение.

Причины берутся из фактических совпадений и признаков. Следующий шаг — предложенное действие для пользователя, не утверждение о неизвестном полном содержании урока. Если алгоритм использовал только описание, UI не утверждает совпадение в названии. Платность не добавляет ранговый бонус.

Qwen получает только текст задачи. После генерации локальный валидатор сохраняет явные ограничения пользователя; противоположное действие/покупка отвергнутой франшизы отклоняются. Предложение всегда подтверждает пользователь.

## Верификация и ограничения

113 pytest с реальной E5, 26 desktop/mobile E2E, Docker/FULL/DEMO smoke и аудит 120 запросов. Детали: audit-1.2.md. Первоначальный 80/40 split использован в отладке, поэтому итог — регрессия. Human labels=0. Нельзя переносить старые nDCG/benchmark или выдавать агентские оценки за независимые.

Task families, слова отраслей и пороги — инженерные эвристики. Возможны нераспознанные формулировки и неполные метаданные. В проверенном наборе 28 частичных ответов и 9 пробелов практического покрытия. Полные закрытые уроки не анализируются и не публикуются. Исторические v4/v5: recommendation-history.md.
