# Оценка рекомендаций

Текущий статус: **человеческой разметки нет, quality-метрики не рассчитаны**. Владелец 12.11.2026 сообщил, что сейчас нет времени размечать кандидатов. Автоматические тесты и примеры перефразирования не подменяют экспертную оценку.

`scripts/evaluate.py prepare` создаёт 32 синтетических бизнес-профиля, фиксированный dev/test split и объединение top-10 кандидатов двух алгоритмов. Строки кандидатов сортируются по ID, источник алгоритма скрыт. Файлы остаются в `.private/`, потому что FULL содержит метаданные предоставленной выгрузки.

Эксперт заполняет `grade`: 0 — не подходит, 1 — косвенно связан, 2 — полезен для задачи, 3 — прямо решает задачу и соответствует контексту. Требуются `label_source=human` и непустое имя/псевдоним `judge`. Эталонные ID берутся только из фактического каталога. Не придумывать пользовательские или материальные идентификаторы.

`calculate` проверяет версию каталога, диапазон оценок, наличие материала и происхождение меток. Неразмеченный материал не считается нерелевантным. Профиль включается в сравнение, только если top-5 обоих алгоритмов полностью размечены. Оставшиеся профили перечисляются явно.

Метрики: P@5 при grade≥2, pooled Recall@5, nDCG@5 с gain=2^grade−1 и MRR@5. Recall относится к пулу размеченных кандидатов, а не всей базе. Макроусреднение отдельно по dev и test. Размер оцениваемой выборки обязателен при публикации результатов.

Dev используется для изменения весов. Test не использовать для настройки и выбора удачных примеров. Нельзя заранее обещать, что персональный алгоритм лучше. Если уступает, публиковать фактический результат и разбирать ошибки. До A/B-теста нельзя делать вывод о росте покупок по offline-метрикам.

При включении E5 пула лексических кандидатов может не хватить. Нужен новый пул для соответствующей версии алгоритма, без перезаписи работы эксперта. Начальные подготовленные файлы: DEMO — 247 пар; FULL — 415 пар, рассчитаны до добавления E5. Они подходят для исходной лексической версии, не автоматически для новой семантической.

Тесты математики метрик содержат известные идеальный/ошибочный порядки и проверку отказа при неполной разметке. Эти искусственные примеры не публикуются как качество рекомендательной системы.


Смысловой разбор 120 запросов в 1.2 — отдельный регрессионный аудит агентом (audit-1.2.md), не источник human labels для calculate. Первоначально отложенные 40 запросов использованы в исправлениях; независимым test их не называть. Подробные оценки и реальные выдачи только в .private. Новая версия алгоритма требует нового пула; старые метрики не переносить.
