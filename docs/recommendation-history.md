# История pipeline v4–v5

Исторический документ; текущая версия описана в recommendation-pipeline.md.

# Подбор материалов — pipeline v5

Переработан 13 ноября 2026 в audit/pr-1-stability после пользовательских контрпримеров. Публичный API Engine.recommend сохранён. Генеративная LLM уточняет запрос отдельно; она не создаёт материалы и не заменяет каталог.

## Разделение ответственности

| Модуль | Ответственность |
|---|---|
| engine.py | Оркестрация шагов и сборка Route, без базы и сети |
| recommendation/intent.py | Нормализация, таксономия, учебная задача и отраслевые ограничения |
| recommendation/eligibility.py | Публикация, отраслевой конфликт, противоположное действие, завершённое/негативное |
| recommendation/index.py | Единственный индекс каталога: TF-IDF и опциональная локальная E5 |
| recommendation/ranking.py | Кандидат как dataclass, ограниченный профильный бонус и стабильное разнообразие |
| recommendation/explanation.py | Действие и фаза по реальному типу материала, без выдуманного содержания |
| recommendation/policy.py | Версии, веса и пороги в одном месте |

Intent и Evidence неизменяемые dataclass. Индекс строится один раз на каталог; один запрос вызывает один embedding encode. Положительные темы истории вычисляются один раз, не внутри цикла по всем материалам. Пустой словарь не ломает запуск. Некорректный внутренний limit отклоняется явно.

## Порядок обработки

1. Нормализовать задачу; пустой и бессодержательный ввод приводит к уточнению. Одно содержательное слово не запрещает поиск.
2. Отфильтровать неопубликованное/пустое, явный конфликт отрасли и противоположное действие. Для personal также исключить изученное/известное/негативное. Случайный пользователь источника не связывается с посетителем.
3. Получить lexical/semantic evidence и оценить уверенность только среди допустимых материалов. Чужая отрасль с высоким similarity не может поднять порог и вытеснить допустимый результат.
4. Построить кандидатов с фактическими сигналами. Сначала релевантность; профиль не может воскресить исключённый материал. Неизвестные метаданные не создают преимущество из-за другого знаменателя.
5. Стабильно выбрать материалы с мягким разнообразием. Объяснение и diagnostic score берутся из реальных сигналов.
6. Определить scope по показанным карточкам, а не слабому непоказанному кандидату. Если отрасль не подтверждена, показать «Общие материалы по задаче», максимум три карточки и только близкие к лучшему результату. Не заполнять пять мест случайными материалами.

Baseline использует те же ограничения запроса и публикации, но не профиль, историю, E5 или персональное разнообразие. Версия baseline topic-baseline-v3; personal lexical-personal-v5 / e5-hybrid-personal-v5. Общий каталог одинаковый. Изменение версии требует нового расчёта, старые метрики не переносятся.

## Проверки и ограничения

66 pytest с реальной E5, 26 desktop/mobile E2E, ruff, typecheck/production Docker-build и FULL smoke прошли. Отдельные тесты: магазин одежды не попадает в медицинскую задачу; неподходящий высокий semantic score не меняет доверие к допустимому материалу; baseline не использует историю; общая подборка короткая; пустые словари не падают; scope соответствует фактически показанным карточкам.

На полном каталоге пользовательские медицинские примеры дают 3 общих материала; магазин одежды и кофейня дают профильные выдачи; короткие налоги/франшиза/ИП работают; квантовая гравитация приводит к уточнению. Подробные трассы остаются локальными.

Независимого доказательства релевантности нет: новый пул .private/evaluation-full-v4-pipeline, 32 профиля, 454 пары, human=0, каталог fd08730e9a5b00f5. Отраслевые словари и пороги — инженерные эвристики, не обещание понимания любой отрасли. В исходном каталоге 26 курсов и нет подтверждённого специализированного курса по лабораториям; общие рекомендации прямо обозначены. Неизвестные URL и TLS внешнего сайта остаются отдельным ограничением.

CPU benchmark: один проход 32 профилей, без HTTP/LLM, p50 personal 18.34 ms / p95 48.50 ms; инициализация 26.66 s. Это характеристика конкретного локального запуска под текущей нагрузкой, не SLA и не метрика качества.


## Исправление ограничения бюджета (v5)

Пользовательский контрпример: «Как увеличить прибыль без увеличения рекламного бюджета?» ранее поднимал сезонную рекламу и обзорный курс из-за совпадения с темой маркетинга. Теперь QueryIntent.constraints содержит fixed_ad_spend при подтверждённой цели прибыли/продаж и формах «без увеличения/роста/повышения рекламного бюджета», «без дополнительных затрат на рекламу», «не увеличивая расходы на рекламу», «с тем же/прежним рекламным бюджетом».

В retrieval ограничительная часть убирается, personal дополнительно ищет повторные продажи, удержание, маржу, конверсию и снижение затрат. Baseline не использует это расширение. Оба режима до confidence требуют свидетельство конкретного механизма из title/description. Маркетинговая метка сама по себе не проходит. Эффективность рекламы/ROAS/ROMI и органическое продвижение допустимы: общего запрета рекламы нет. Специализированные отраслевые заголовки без указанной отрасли и glossary для практической задачи исключаются. Короткая подборка <=3 и порог .75 от лучшего не заполняются слабым хвостом.

Объяснения показывают механизм, а предлагаемый следующий шаг относится к нему; это предлагаемое действие, не утверждение о неизвестном полном содержании урока. Новый тест защищает отсутствие ложного отсечения, когда маркетплейс назван в запросе, и не требует обязательного включения любой допустимой статьи.

Верификация v5: 78 pytest с реальной E5, ruff, Docker/FULL smoke 8. Live trace хранится только в .private/context/constraint-v5-live.json. Для исходной фразы остался один материал о повторных продажах. Старые оценки/CPU benchmark и 26 E2E выше относятся к v4. Независимой разметки v5 нет. Не заявляется универсальное распознавание отрицаний; другие ограничения требуют своих проверяемых правил. Предыдущий пример кофейни с третьим общим материалом остаётся отдельным недостатком.
