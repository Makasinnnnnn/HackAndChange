# Ответы жюри

**Почему не чистая LLM?** Рекомендации должны ссылаться на существующий каталог, соблюдать доступ, учитывать изученное и воспроизводиться. Эти ограничения обеспечивают нормализация и ранжирование. Локальная E5 отвечает только за текстовую близость, а не придумывает материалы.

**Чем отличается от поиска?** Кандидаты проходят персональное ранжирование с реальными метаданными, форматом, срочностью и явной обратной связью. Пользователь получает порядок и следующее действие. Диагностика показывает вклад факторов. Это не доказательство роста покупок.

**Как проверяли качество?** Есть независимый baseline, 32 профиля и инструмент слепой человеческой оценки. Метки ещё не получены, поэтому P@5/nDCG не заявлены. Unit/API/E2E проверяют поведение системы, а не заменяют оценку релевантности человеком.

**Как работает холодный старт?** Текущей задачи достаточно. Анкету можно пропустить. Если задача неопределённая, система предлагает направления и уточнение. Отсутствующий опыт не превращается в «начинающий» автоматически.

**Какая реальная история использована?** В дампе есть записи на курсы, завершения уроков и оценки. Полный журнал просмотров не подтверждён. В браузерной версии используются собственные явные события тестового профиля, сохранённые в PostgreSQL. Привязка к исходным пользователям не выполнена.

**Как исключаете пройденное?** Перед персональным ранжированием исключаются материалы с отметками completed/known и not_relevant. Проверяется повторным запросом. Отметку можно снять.

**Объяснения настоящие?** Текст строится из реально использованных факторов. Если сложность или стадия материала неизвестна, такое соответствие не утверждается. Диагностика отдельно показывает score до разнообразия, штраф формата и rank_score при выборе позиции.

**Зачем PostgreSQL 18, если источник 16?** Дамп создала утилита pg_dump 17.6, формат 1.16. pg_restore 16 реально отказал. Восстановление на имеющемся PostgreSQL 18 прошло в изоляции. Версия и digest закреплены. Рабочие данные приложения хранятся отдельно.

**Как защищаете платные уроки?** Импорт не читает их тела, исходный HTML не рендерится. API-модель запрещает содержимое для реального каталога и платных примеров. Только короткие метаданные и ссылка, без обещания права доступа.

**Почему часть ссылок отсутствует?** У исходных записей URL часто представлен slug. Подтверждённые пути статей/курсов нормализуются; дополнительно используются канонические ссылки, найденные в публичных статьях. Остальные остаются nullable. Мы не подменяем неизвестное выдуманным адресом.

**Можно ли работать без интернета?** После сборки и локальной подготовки данных основной поиск работает без внешних API. Скачивание зависимостей и опциональных публичных весов требуется заранее. Переход к сайту первоисточника требует сети.

**Сколько стоит AI?** Обязательного внешнего AI API нет. Основной режим — CPU TF-IDF и правила. Опциональная E5 работает локально. Облачный inference и платные модели не подключены.

**Как измерить рост конверсии?** Подтверждённая покупка из аналитики платформы, стабильная рандомизация по пользователю, заранее определённые окно, выборка и MDE. Клик по платному продукту покупкой не считается. Пока эффекта не измеряли.

**Что при росте каталога?** Сейчас индекс в памяти соответствует небольшому каталогу. Следующий шаг — кеширование индекса и замер p95/потребления памяти. Выделение retrieval-сервиса или векторной БД оправдывается нагрузочным измерением, а не названием технологии.

**Главные ограничения?** Неразмеченная релевантность, неполные подтверждённые URL, отсутствие исходной пользовательской авторизации и эксперимента по покупкам. Прототип локальный, не production-развёртывание.
