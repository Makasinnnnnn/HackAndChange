# Бинарная CSV-диагностика релевантности

Это дополнительный инструмент `score_blind_eval.py`, не замена градуированному `scripts/evaluate.py`. Публичный шаблон содержит только синтетические PLACEHOLDER-значения. Реальные выдачи, заполненные CSV и подробные отчёты сохраняйте только в `.private/`.

Колонки top_1_material_id…top_10_material_id — решение, baseline_top_* — отдельный baseline capture. Оценки задаются списками `human_relevant_ids` / `human_irrelevant_ids` через `|` или `;`. Обе пустые колонки означают отсутствие оценки; явно отрицательный пул учитывается нулём. Пустой реально снятый baseline дополнительно обозначается `baseline_captured=true`.

Оцените весь объединённый пул. Неразмеченный пул исключается целиком для обеих систем, неизвестное не считается отрицательным. Пустая выдача решения с известными релевантными кандидатами даёт ноль. Противоречивые метки, повтор query_id/ID и пропуски позиций внутри ранжирования — ошибки.

Precision@k имеет фиксированный знаменатель k; pooled Recall относится к известному пулу; NDCG бинарный, IDCG учитывает известные релевантные материалы. Пары out_of_scope учитываются отдельно, включая ошибочные непустые ответы. CSV сам по себе не доказывает автора и независимость меток.

```powershell
python audit/score_blind_eval.py --input .private/blind-eval.csv --output .private/blind-eval-report.md --k 3
```

Отчёт не перезаписывается, для следующего расчёта выберите новое имя. Примеры, известные разработчикам или использованные при настройке, не являются независимым holdout. Источник меток и правила формирования выборки фиксируются до сравнения.
