## 1. Безубыточность

**Прямые совпадения в каталоге.** `rg -i "безубыт|break-even|breakeven"` по `backend/data/demo.json`
— **0**. По `material_tasks()`: материала с задачей `breakeven` — **0 из 36**. Слово
«безубыточность» в каталоге не встречается ни в title, ни в description, ни в tags/topics.

**Смежные материалы** (реально существуют, текстом про вклад в покрытие постоянных затрат):

- `demo-margin` — «Цена, себестоимость и маржа заказа»: *«Разложите цену на переменные расходы и вклад в покрытие постоянных затрат»* — это ровно половина формулы безубыточности;
- `demo-unit` — «Юнит-экономика простыми словами» (задача `profitability`);
- `demo-finance-course` — «Управленческие финансы для собственника»;
- `demo-opening-cafe` — «Перед открытием кофейни: что проверить» (отраслевое совпадение `food`).

**Что возвращает сейчас `[static, manual-sim]`.** Запрос «как посчитать точку безубыточности для кофейни»:

```
intent: tasks=[breakeven], topics=[Маркетинг], sectors=[food], clarification=null
excluded: unsupported_task=22, sector=8, incidental_document_mention=6  (36/36)
eligible=0 → engine: "В каталоге нет подтверждённого материала по этой конкретной задаче..."
```

Вывод: честный отказ срабатывает, **но это не «нет точного — вот смежное»**. Пользователь не видит
ни `demo-margin`, ни `demo-unit`, хотя формула безубыточности выводится из них за один шаг.
Причина двойная: (а) в каталоге нет карточки с задачей `breakeven`; (б) `unsupported_task` — абсолютное вето,
оно не допускает смежную задачу `profitability`/`costing` даже как fallback.

**Вердикт: не покрыта.**

## 2. Конверсия

**Прямые совпадения.** `rg -i "конверс"` по каталогу — **0**. Но `rg -i "воронк"` — **3**, и это
настоящие материалы про воронку: `demo-sales-funnel`, `demo-sales-course`, плюс упоминание в
`demo-sales-course` (description). По `material_tasks()`: задачи `funnel` есть у
`demo-sales-funnel` и `demo-sales-course`, задача `conversion` — **0 из 36**.

**Смежные материалы:** `demo-sales-funnel` («Продажи без догадок: найти узкое место» — «Разделите
обращения, предложения, сделки и повторные покупки. Сравните этапы воронки»), `demo-ad-economics`
(«сколько стоит клиент»), `demo-marketing-map` («найдите место, где теряются клиенты»),
`demo-repeat-sales` (retention), `demo-sales-course`.

**Что возвращает сейчас `[static, manual-sim]`.**

Запрос «как повысить конверсию сайта»:

```
intent: tasks=[conversion], topics=[Продажи], clarification=null
excluded: unsupported_task=27, incidental_document_mention=9 → eligible=0 → 0 карточек
```

Запрос «клики по рекламе есть, а покупок нет» (естественная формулировка той же задачи):

```
intent: tasks=[] (синоним не распознан), topics=[Маркетинг],
        clarification="Пока определена только общая тема..." → engine возвращает 0 карточек ДО retrieval
Если ранний clarification убрать (в симуляции): 7 кандидатов, top-5 =
  demo-ad-economics 0.269 | demo-marketing-course 0.191 | demo-marketing-map 0.170 |
  demo-audience 0.165 | demo-marketing-podcast 0.128
```

Ключевой момент: даже если убрать ранний clarification, **обе карточки про воронку в top-5 не попадают**,
потому что у них нет task-evidence `conversion` (их задачи — `funnel`/`retention`).
То есть проблема не в отсутствии контента, а в отсутствии семейства задач.

**Вердикт: частично.** Контент есть, доставки нет.

## 3. Снижение расходов без увольнений

**Прямые совпадения.** `rg -i "ФОТ"` — 2 совпадения, но **это ложные срабатывания**:
подстрока «фот» в слове «фотографий» (`demo-maps`). Термина «ФОТ» как фонда оплаты труда в каталоге нет.
`rg -i "cost_reduction"` — 0; `material_tasks()` не даёт `cost_reduction` ни одному материалу.
`rg -i "расход"` — 13 упоминаний, но это расходы вообще (`demo-margin`, `demo-market-template`,
`demo-ad-economics`, `demo-business-start`, `demo-opening-cafe`), не «сокращение ФОТ».

**Смежные материалы:** `demo-margin` (статьи расходов и вклад в покрытие), `demo-cash-template`
(«выплат команде» в платёжном календаре), `demo-finance-course` (финансовые решения),
`demo-market-template` (таблица расходов по товару — узко, маркетплейс).

**Что возвращает сейчас `[static, manual-sim]`.**

```
"как сократить расходы, но не увольнять людей"
  intent: tasks=[cost_reduction], topics=[Финансы], constraints=[] (!!)
  excluded: unsupported_task=27, incidental_document_mention=9 → 0 карточек

"оптимизировать ФОТ без сокращений"
  intent: tasks=[] (ФОТ не входит в regex cost_reduction), constraints=[]
  excluded: no_informative_anchor=36 → 0 карточек
```

Два независимых дефекта:

1. `unsupported_task` — в каталоге нет материала с `cost_reduction`, значит вето на всё;
2. лексика — «ФОТ» не покрыт regex `tasks.py:70-71` (`сократ|снизи|снижен|оптимизац ... расход|затрат|издерж`),
   а «не увольнять» не превращается в `constraint` (`intent.py:328` ждёт формулировку «без увольнени…»).
   То есть самая человеческая часть запроса — «без увольнений» — не парсится вообще.

**Вердикт: не покрыта.**

## CRAG / step-back: есть ли ветка `no_exact_match`

**Проверено:** `rg -i "no_exact_match|step_back|stepback|crag"` по всему репозиторию
(кроме `audit/`) — **0 совпадений**. Ветки под таким именем **нет**; в API-контракте `Route`
(`models.py:93-107`) нет поля `no_exact_match`.

**Что фактически есть в `engine.py`** (это не CRAG, а набор отказов):

| Механизм | Строки | Поведение |
|---|---|---|
| `intent.vague` | 89-92 | общий вопрос «привлечь клиентов / финансы / запустить бизнес?» — 0 карточек |
| unknown-gate по лексике | 112-119 | если нет topics/tasks и `word_peak<0.10` & `char_peak<0.18` → «нет уверенного совпадения» |
| unknown-gate семантический | 120-128 | только при включённой E5; при выключенной не работает |
| нет кандидатов после фильтров | 196-200 | clarification «точного материала не нашли» |
| notice о слабом совпадении | 230-231 | `max(relevance) < 0.20` → «Совпадение слабое: это ближайшие материалы, а не точный ответ» — **но только если карточки уже есть** |
| general-scope по отрасли | 216-228 | при несовпадении отрасли — <=3 общих материалов + notice |

**Вывод:** для всех четырёх тем система умеет только «честно промолчать» (0 карточек) либо, если
карточки всё же нашлись, пометить их как слабые. **Step-back (расширение задачи до смежного семейства
с явным `no_exact_match` и маршрутом «начните с этого») отсутствует.** По правилу этой фазы это
**P0-фикс**.

Важно: это тот же корень, что P0-1/P0-2/P0-3 прошлого аудита (ранний clarification, anchor-gate,
отсутствие семейств задач). В этой сессии код не правится — фиксы только в плане.
