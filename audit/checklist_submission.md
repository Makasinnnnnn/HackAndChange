## 7. Известные ограничения — что обязательно указать в README/презентации

Это текст для честного раздела «Ограничения» (в README уже есть ссылка на `docs/limitations.md`;
добавление этих пунктов — **правка кода/документации, требует отдельного go**, здесь только формулировки):

- [ ] **P0-A:** ветки `no_exact_match` + step-back нет. Запрос вне каталога → уточнение, но без
      «более общей подборки / маршрута изучения». PDF (с. 14) требует «уточнение, более общую подборку
      **или** маршрут изучения» — уточнение у нас есть, остальное в плане.
- [ ] **P0-B:** `unsupported_task` — жёсткое вето; задачи из семейств (конверсия, дебиторка,
      безубыточность, снижение расходов) на DEMO-36 дают 0 карточек.
- [ ] **P0-C:** `no_informative_anchor` не снят; часть естественных формулировок отсекается до retrieval.
- [ ] **Human labels = 0** на момент сдачи: превосходство над baseline и бизнес-эффект **не доказаны**.
      Оценки агента по 120/150 запросам использованы в настройке и **не являются** независимым holdout.
- [ ] **Каталог**: по умолчанию **DEMO-36** (авторская синтетика). Полный каталог **1473** материала —
      только локально через `compose.full.yaml` + `.private/catalog.json`; в архив не входит.
      507 из 1473 URL остаются неподтверждёнными (`url=null`).
- [ ] **E5 опциональна**, по умолчанию лексический TF-IDF; влияние E5 на человеческую релевантность
      не установлено.
- [ ] A/B-план описан, но **не проведён**; конверсия покупок не измерялась.

- [ ] Проверить, что эти ограничения не противоречат тому, что написано в презентации (одни и те же
      цифры в PDF и README, иначе жюри это заметит).
