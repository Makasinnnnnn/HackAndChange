# Работа с исходниками

Запуск и окружение описаны в [инструкции](START_HERE_JURY.md). Для изменений используйте отдельную ветку; опубликованные теги не переписывайте. Сохраняйте API-контракт, изоляцию сессий и проверку признаков каталога.

Backend: pytest и `ruff check backend scripts audit`. Frontend: typecheck, production build и desktop/mobile E2E на отдельном DEMO. Для реальной E5 укажите TEST_SEMANTIC_MODEL_DIR. Перед публикацией выполните `scripts/check_version.py`, `scripts/check_public_files.py` и `git diff --check`; просмотрите состав файлов.

Исходный дамп, реальный производный каталог, история, секреты и локальные модели не входят в Git/образы/архивы. Публичные fixtures и изображения — авторский DEMO. Не менять исходную аудиторскую БД. Метрики качества публиковать с происхождением оценок и размером выборки; score не является вероятностью релевантности.
